# E1.2：HDMI EDID 颜色能力离线实验（历史方案）

**历史定位：只提供离线 EDID 分析、生成和测试工具，没有在本分支内核中实现 U27P10 伪色的正式修复。**

该分支继承 E1.1-HDMI600（`91629bd10c5d40f41a6df76e8daf96a87ab0ed07`），不修改当时的 Display13 多输出驱动、WhateverXe Graphics 0.4.0、EFI 或 HDMI600 运行补丁。

## 一、提出背景与后续发现

最初参考 WhateverXe [Issue #40](https://github.com/b00t0x/WhateverXe/issues/40) 的紫色画面案例以及 [Issue #41](https://github.com/b00t0x/WhateverXe/issues/41) 的 300→600MHz 模式准入讨论，推测 YCbCr、Deep Color 和 HDR 声明可能共同影响显示器颜色。

**2026-11-19 的本机实测已经将原因进一步缩小：** Lenovo Yoga Pro 14s IRH8 / A7A0 的 U27P10 4K30 在 YCbCr 10 bpc 时伪色；后续仅限制 Deep Color 后，仍使用 YCbCr 4:4:4，但以 8 bpc 正常显示。有效的最小化修复在 [WhateverXe 0.8.3 EDID A/B 分支](https://github.com/Lanye-z/WhateverXe-yogapro13900/tree/experiment/wex-0.8.3-yoga-edid-ab)，启动参数为 `-wex-yoga-hdmi-edid-deep8`，**不属于此旧分支**。

## 二、离线识别与生成

连接外接显示器后，可先导出候选 EDID：

```bash
ioreg -p IOService -l -w0 | grep IODisplayEDID > ~/Desktop/edid-list.txt
python3 e12/tools/edid_rgb8.py ~/Desktop/external-edid.bin --inspect-only
```

`ioreg` 可能同时包含内屏和外屏 EDID；不能将第一条直接当作 HDMI。工具可读取 EDID 二进制、十六进制文本或 `ioreg` 文本；多个 EDID 候选时要求指定 `--index N`，应先核对 VID/PID 和设备型号。

生成离线测试文件：

```bash
python3 e12/tools/edid_rgb8.py ~/Desktop/external-edid.bin \
  --out ~/Desktop/E1.2_RGB8_Output
```

产物及含义：

| 文件 | 用途 |
| --- | --- |
| `ORIGINAL_EDID_BACKUP.bin` | 原始 EDID 备份 |
| `RGB_ONLY.bin` | 删除 CTA 中部分 YCbCr 声明，不关闭全部 Deep Color 与 HDR；不保证输出 8 bpc |
| `RGB8_STRICT.bin` | 进一步声明 8 bpc，限制 HDMI/Forum Deep Color 并清理部分 CTA HDR 能力 |
| `REPORT.json` | 厂商/产品识别、校验和与改动报告 |
| `RGB_ONLY/DisplayVendorID-*/DisplayProductID-*` | 对应 macOS EDID plist 覆盖文件 |
| `RGB8_STRICT/DisplayVendorID-*/DisplayProductID-*` | 更严格的 macOS EDID plist 覆盖文件 |

脚本会校验 EDID 校验和及扩展块数量，尽量保留已识别的 CTA 视频格式、详细时序、HDMI 600MHz 声明及 SCDC 标志。若设备只有 4:2:0-only 形式的 4K60 时序，工具会拒绝可能导致模式丢失的删除操作。

## 三、手工测试与回退原则

这些工具**不会自动安装覆盖、修改 EFI、运行 sudo 或编辑 `/Library`**。如要研究历史方案，只能由管理员主动备份、安装并验证单一版本，覆盖文件通常位于：

```text
/Library/Displays/Contents/Resources/Overrides/
  DisplayVendorID-xxxx/
    DisplayProductID-yyyy
```

在测试前核对显示器的真实连接方式：机身原生 HDMI 与 USB-C/扩展坞 DP→HDMI 转换路径不同。分别记录 1080p、4K30 的颜色与稳定性；4K60 是否出现及其正常与否需要另行核查。若颜色变差，恢复**该产品级**覆盖文件的备份，不得误删整个厂商目录；保留可启动的恢复 EFI。

## 四、静态测试

```bash
python3 -m py_compile e12/tools/edid_rgb8.py
python3 -m unittest discover -s e12/tests -v
```

静态测试通过只证明生成器按预期工作，不证明系统已加载覆盖，也不证明 4K60 或 HDMI 热插拔稳定。

**建议：当前 U27P10 已通过 0.8.3 的 Deep8 最小能力限制恢复颜色，除非为论文/对照实验，不再优先使用 E1.2 整体 EDID 覆盖。**
