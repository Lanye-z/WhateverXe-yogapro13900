## 最关键的失败路径
`WEXYogaHDMI2HighLast` 和 `WEXYogaHDMI2WMEvent` 同为 uint64_t[6]：

| schema | seq | pipe | pixel clock | status | armed pipe |
|---:|---:|---:|---:|---:|---:|
| 1 | 22 | **1** | **533250000 Hz** | **5** | **3（未武装）** |

代码里 `yogaHDMI2TryPrepare()` 在调用 SCDC 前返回状态 **5**，因为 `IORecursiveLockHaveLock(controller+0x9B8)` 为 false。真正的 Display13 WM 入口不是 V1 假设的“原生 owner recursive lock 已持有”路径。**不能简单移除锁检查后从此处同步调用 native I²C；需要在可证实的 owner/DDC gate 内接入或采用异步安全排程。**

`WEXYogaHDMI2SourceLast` 未记录。现有 `WEXYogaHDMIColorLive` 在 HDMI mask=0x2、powered mask=0x7 时观测：

- HDMI **Pipe1** `TRANS_DDI_FUNC_CTL=0x90010200`
- enable=1，High TMDS Ratio bit4=0，Scrambling bit0=0，8bpc field=0。

与前次正常 4K30 的 Pipe2 不同，说明源端绝不可固定 Pipe2。因为 source 尚未置位，不能借这次失败认定 PLL/PHY 有缺陷。

## 第二条独立线索：DDC Bus 2 的 SCDC 请求失败

`hdmi_registry.txt` 的 `N97FBGMBusFirst11`，按照本仓库已有 21x uint64 诊断结构解码：

| seq | DDC bus | I²C send/reply address | send/reply bytes | native/result |
|---:|---:|---|---|---|
| **11** | **2** | **0xA8 / 0xA8** | **1 / 1** | **0xE00002ED / 0xE00002ED** |

`0xE00002ED = kIOReturnNotResponding`，不是 kIOReturnBadArgument。参照 Apple IOReturn.h：https://leopard-adc.pepas.com/documentation/Darwin/Reference/IOKit/IOReturn_h/index.html

另外，First1..4 对 `0xA0` 的 EDID 读取成功，说明不能简单说整个 DDC Bus2 失效。但 `0xA8` 的失败是某个时刻真实的 SCDC transaction 失败；**无法仅由该日志证明来源于本实验 Kext、原生 Apple 代码或其他历史路由**。在当前 V1 最近一次 WM 记录中，SCDC 被状态5提前阻断。必须先获取 DDC 调用方来源、锁状态、时序，再考虑修复。

中间请求序号没有完整保留，First 16 + Last 并非完整通信历史。没有成功 SCDC 0x20=0x03 的读回证据。

## 下一版必须具备的决策门槛

1. **不准从当前 WM callback 直接无锁执行 native I²C**；维持 V1 的拒绝路径，不能将状态5“修正”为假通过。
2. 将 HDMI2 的计划与 Native SCDC request 分阶段：WM 可只读记录 pending timing（这里是 533.25MHz），实际 I²C 必须安排在验证过的原生锁/生命周期入口。
3. 给 `0xA8` 读写单独做 request type/address/bus、原生返回、readback、调用者/时序的定界记录；SCDC 失败不允许 source bit0/4。
4. 原生 DDI pipe 号动态识别（本次 Pipe1），保留 8bpc、Deep8、SST、120Hz；对 340MHz 以下正常模式不引入额外 SCDC。
5. 在 SCDC `0x20` 回执确认前不发布 armed pipe；高 TMDS 源端只能在**对应 pipe 的原生启用写**发生前按掩码 `|0x11`，需要静态+实机观测确认该写确实被 existing MMIO hook 接获。
6. **安全恢复优先于重新重现问题**；只在内屏正常时做只读采样。若要回退，先存盘，再于关机后拔开机身 HDMI、使用已验证的旧 EFI 启动，避免冒险在线切换。该步骤减少风险但不保证绝对不会黑屏。

## 结论

V1 **确实加载**，但 HDMI2 的 *hardware repair branch 没跑完*（WM status5，armed3，源端0），4K60 物理黑屏仍在。另有一次 DDC bus2 / SCDC 0xA8 返回 `kIOReturnNotResponding`；后者需要区分调用源与通信失败原因，不能直接拿来证明显示器不支持 HDMI2。**不应再次要求用户立即切换刷新率，也不应继续使用 V1 尝试多次 4K60。**
