# Yoga 82Y7｜HDMI 4K30 新基线（20:19:32，2026-11-20）

**输入：用户上传的 `Yoga_HDMI4K60_hdmi30_20261120_201932.zip`（本报告只汇总技术数据，不上传原始 ioreg / EDID / 显示器序列号）。** 当前仍是 4K30 正常基线，不是 4K60 黑屏测试，也不是修复成功证据。

## 1. 真实加载与屏幕状态

- macOS Tahoe 26.7.1（25G241），核显 `8086:A7A0` rev04，Metal 2，1536MB，`WhateverXe 0.8.3`，`Lilu 1.7.3`。
- 原生 `AppleIntelTGLGraphicsFramebuffer 16.0.0` 实际加载 UUID `B6078743-F795-3202-A55E-EA690FA40949`。与此前原生 Mach-O 反汇编的 donor 完全吻合（UUID；本 ZIP 本身不含 donor SHA256）。
- 3 个 `IOFBCurrentPixelClock`：FB0 **775690000 Hz**、FB1 **148500000 Hz**、FB2 **297000000 Hz**。FB0 的像素时钟符合研究中的 3K120 配置；但 `system_profiler` 当前只枚举 27B2 与 U27P10，不能单凭像素时钟证明内屏实物 OSD 的刷新率。
- `system_profiler`：27B2 **1920×1080@60**；U27P10 **3840×2160@30**（HiDPI UI 1920×1080）。这是本次状态，前一次 27B2@75 / 内屏@60 不应混用。
- 对应 `IOFBTimingRange.maxPixelClock` 3 个是 **800 / 720 / 600MHz**，符合 eDP admission 与 HDMI600 扩容。
- `WEXYogaHDMI600Ready=Yes`, `Status=4`；`WEXYogaHDMIEDIDABApplied=Yes`；`WEXYogaEDP120AdmissionStatus=4`；`WEXYogaSSTHookStatus=4`、`CapabilityMasked=Yes`；`N97FBOutputHooksReady=Yes`。
- 这次采集仍未填写 `USER_OBSERVATION.txt`；不能以 `system_profiler` 替代外屏 OSD 的物理实况。

## 2. 原生 HDMI GPU 源端寄存器（有效 ColorLive 236 字节）
`WEXYogaHDMIColorLive` schema=1，valid=1，HDMI Pipe mask = `0x4`，powered Pipe mask = `0x7`。

| Pipe | `TRANS_DDI_FUNC_CTL` | 判读 |
|---|---|---|
| 0 | `0x8A100106` | 不是机身 HDMI B；不要把该 DP/eDP 控制字的 bit0 当成 HDMI scrambling |
| 1 | `0xB2030002` | 不是机身 HDMI B |
| **2** | **`0x90030200`** | **机身 HDMI B，enable bit31=1，high-TMDS bit4=0，scrambling bit0=0，8bpc 字段=0** |

- Pipe2 `PIPE_MISC=0x01800810`、`VIDEO_DIP_CTL=0x00001100`。与此前 4K30 YCbCr444/8bpc 修复结果一致。
- 297MHz 是 HDMI 1.4 速率范围，低速模式源端 bit0/4 不开符合规范；**不能由此判定 4K60 时这两位仍为 0**。

## 3. DDC/GMBUS：可证明的和不能证明的

- 已发布的 `N97FBGMBusLast` 是 **schema3、序号31、bus2**、native=`0xE00002C2`（`kIOReturnBadArgument`），sendAddress=0。它不是地址 `0xA8` 的 SCDC 失败。
- 第一批 16 条摘要里，#1/#2/#5/#6 是 `sendAddress=0xA0` 且成功的 EDID 读取；#3/#4/#7–#13 主要为 `sendAddress=0x74` 且失败；#14–#16 地址为0且 BadArgument。
- **记录的初始16条和最后第31条都未发现 `0xA8`，但中间 #17–#30 未完整保留。** 因而不能声称这台机型 4K30 下任何 SCDC 都没执行，更不能推断 4K60 下没有 SCDC。
- `N97FBGMBusHistoryLast` 为空，没有可据此重建的完整顺序与内容。

## 4. 相比之前基线值得注意的变化
此前 17:26:54 的采集中 FB0 实际 60Hz；本次 FB0 像素时钟达到 775.69MHz，而两台外屏分别 148.5 和 297MHz。若将 U27P10 切成典型 594MHz 的 4K60，像素负载和共享 clock/DBUF/WM 压力都会增加。因此 **即便源端 bit0/4 与 sink SCDC 都正确，也仍需要评估多管线的时钟/WM 与失败回滚**。不能把纯 SCDC 修复当作已验证完整答案。

## 5. 下一步软件落地
1. **已完成：** `hdmi2_8bpc_plan.hpp` 将 RGB/Y444 8bpc 的高速要求表达为 sink `0x20=0x03` 和 GPU source `0x11`，不会影响正常 297MHz 模式。
2. **已加入 CI Mock：** `hdmi2_scdc_prepare.hpp` 在成功 SCDC readback 之前不放行 source flags，并考虑失败 rollback 与热插拔 connection generation。**尚未接上真实 Apple I²C 和 Display13；CI 通过不等于 GPU/显示器实机成功。**
3. **尚未解决：** Display13 HDMI 输出前的无回归执行切入点（历史 standalone `LightUpTMDS` route-only 导致 Metal 丢失）、Apple donor DDC 的实际同步 ABI 与锁顺序、真实 4K60 的 SCDC/MMIO 时序。
4. 当前成功 EFI/WhateverXe 不改、用户不需要为基线再重复采集，避免为取证无防护地重现黑屏。
