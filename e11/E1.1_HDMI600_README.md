# E1.1-HDMI600: Yoga Pro 14s IRH8 / A7A0 optional test

EXPERIMENTAL / NOT VALIDATED ON PHYSICAL YOGA. This build never installs drivers or edits EFI.
The known-good D1.1, E1.0 and NootedGreen recovery EFIs must remain untouched.

## Evidence
- WhateverXe issue 41: https://github.com/b00t0x/WhateverXe/issues/41
- User's E1 HDMI IORegistry snapshot: the 27B2 HDMI framebuffer TimingRange contains little-endian 0x11e1a300 = 300MHz at byte offset 40; active 1080p60 pixel clock 148.5MHz. Two other display framebuffers advertise 720MHz.
- User's U27P10 EDID has a ~533.25MHz 4K60 timing. The current HDMI 300MHz cap excludes it.
- The user's Tahoe donor UUID B6078743-F795-3202-A55E-EA690FA40949 matches issue 41. Still require an EXACT 28-byte instruction match and getOnlineInfo symbol position: UUID alone is insufficient.
- Issue 41 author used a SEPARATE RGB8 EDID override to fix purple HDMI colors before the clock patch. This experiment DOES NOT fix colors.
- The author patched desktop ADL-S / Display12. The Yoga mobile 13900H instead uses the Display13 backend; do not cherry-pick that installation hook without adaptation.

## Experimental implementation
- Pinned E1.0 source plus single archived D CTL2 eDP line unchanged.
- Add exact-match 300->600MHz HDMI timing admission inside the Display13 backend, only if mobile adlpDisplaySelected, Display13, qualified framebuffer clocks, correct load index, function offset and 28 source bytes match.
- Change only four immediate bytes at offset 0x2E780; no Apple driver file is ever changed on disk.
- Default OFF. New boot flag on THIS compiled Kext only: -wex-yoga-hdmi600.
- IORegistry root diagnostic keys: WEXYogaHDMI600Requested, WEXYogaHDMI600Ready and WEXYogaHDMI600Status. Status codes: 0=off, 1=gate rejected, 2=donor mismatch, 3=write failed, 4=installed.
- No changes to H264/AppleGVA, HDMI color state, 4K DP dock link, 120Hz eDP, USB4/Thunderbolt or existing Graphics 0.4.0.
- Passing build/tests is NOT proof of 4K60 real hardware output. No SCDC/scrambling implementation is added; a 600MHz timing range alone is not sufficient.

## Boot validation (separate TEST EFI only)
1. Copy the existing successful E1.0 USB EFI into a third EFI with a separate boot entry. Save D and E1.0 unchanged.
2. Replace ONLY WhateverXe.kext with the E1.1 experimental Kext. Preserve Graphics 0.4.0 and other original Kexts. First boot with no new HDMI600 boot argument to check baseline behavior.
3. With the recovery EFI ready, add -wex-yoga-hdmi600 only to the new test EFI. Cold boot on internal display. Test 1080p HDMI first, then 4K HDMI.
4. Read status: ioreg -p IOService -l -w0 | grep -E 'WEXYogaHDMI600|IOFBTimingRange|IOFBCurrentPixelClock'
5. Status 4 plus HDMI TimingRange 600MHz confirms only that the guarded patch took effect. Do not assume that 4K60, RGB output, color correctness, or hotplug is fixed.
6. If 4K60 appears, test with monitor OSD input timing. Observe for display loss, purple/green colors, GPU hangs, or restarts.
7. If any failure occurs, reboot with original E1.0/D EFI. Never hot-unplug the external RTL9210B macOS system disk during live macOS execution.

## Build
GitHub Actions workflow e1.1-hdmi600.yml checks the exact source overlay and passes upstream tests and the opt-in 28-byte matcher sanitizer test, then builds a Kext-only RELEASE zip. Artifacts are build evidence, not physical-hardware validation.
