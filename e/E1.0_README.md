# WhateverXe E1.0 — Yoga Pro 14s IRH8 (82Y7) multi-output experiment

**EXPERIMENTAL; not yet hardware validated.** This is a separate E development branch based on archived D1.1. Never replace the daily-use D EFI or `archive/D1.1-2026-11-05`. This branch builds only a Lilu plugin Kext, not Graphics, not an EFI.

## Design (Issue #38, initial minimal merge)
- Pin [Thatisjigen/WhateverXe `acer/current`](https://github.com/Thatisjigen/WhateverXe/tree/acer/current) at `f7b9bf2229d323e37e8b1dfb87182f005eb7a277`. Retain its multi-Pipe clocks, full VBT output map, USB-C DP Alt Mode, hotplug and firmware eDP boot handling.
- Take **only one line** from archived D1.1 `src/WhateverXe/kern_alderlake_n.hpp` at line 243, making `dpSource(... panel=true)` accept `TRANS_DDI_FUNC_CTL2 bit 3` while rejecting other bits. Both header files are byte-for-byte identical except that line; verified source blob SHAs enforced by `e/tools/prepare_e.py`.
- **Do NOT** copy D1.1's `kern_xe.cpp`, forced eDP software `mode=1`, panel-only VBT masking, D diagnostic hooks, video driver code or custom boot arguments. The author's upstream `kern_xe.cpp` must remain unchanged.
- Continue using your **already installed signed WhateverXe Graphics v0.4.0** for the first controlled test (not included in this build). Compatibility with the newer upstream Kext has not been independently validated.

## Build on macOS
Requirements: Intel macOS with Xcode CLT, Python 3, Git; build will fetch the pinned upstream, MacKernelSDK and Lilu 1.7.2.

```bash
git clone --branch E1.0 --single-branch https://github.com/Lanye-z/WhateverXe-yogapro13900.git
cd WhateverXe-yogapro13900
bash build_E_on_macos.command
```

Output: `OUTPUT_E/WhateverXe_A7A0_E1.0_Experimental_RELEASE.zip` plus `BUILD_INFO.txt`, `build.log`, and reviewed single-line diff. It neither installs a Kext nor changes EFI/Graphics. `.github/workflows/e1.0.yml` does the same in GitHub Actions and uploads a test package on build success.

## First real-device test — use a *separate* USB/test EFI
1. Keep the working D EFI and the NootedGreen recovery EFI intact. Duplicate an **EFI already known to boot with WhateverXe**; do not mix NootedGreen and WhateverXe in the same enabled Kext configuration.
2. In the duplicate only, replace `WhateverXe.kext` with E1.0 RELEASE and refresh its OpenCore Kext entry/snapshot. Keep Lilu/AMFIPass and the existing Graphics 0.4.0 baseline. Do not touch Graphics binaries or system GPU libraries.
3. Remove `-wex-a7a0-panel-only` from the E test boot-args; this old D flag does not exist upstream. Leave other known working arguments unchanged. Do not add a forced `mode=1` modification.
4. Boot **without an external monitor** first. Confirm normal 3072x1920 eDP, no mode-set failure, `kmutil showloaded` and `system_profiler SPDisplaysDataType`. Verify Metal / hardware video decode separately; booting alone does not establish acceleration.
5. Only after internal display and acceleration pass: connect USB-C DP display; check extension, detach/reattach, WindowServer and kernel logs. Test HDMI only if hardware routing actually supports it. 120 Hz is an *unverified stretch target*, not promised.
6. For black screen, freezes, loss of accelerated graphics or boot failure: boot the **untouched D/recovery EFI** and collect the E boot log from the same attempt where possible. Do not replace the stable EFI.

Useful commands once booted:
```bash
kmutil showloaded | grep -Ei 'WhateverXe|NootedGreen|AppleIntelTGL'
system_profiler SPDisplaysDataType
ioreg -p IOService -l -w0 | grep -Ei 'WEX|Framebuffer|Metal' | head -n 80
log show --last boot --style compact --predicate 'eventMessage CONTAINS[c] "mode set" OR eventMessage CONTAINS[c] "clockFaulted" OR eventMessage CONTAINS[c] "TGL accelerator"' 2>/dev/null | tail -n 90
```

## Scope and limits
A successful GitHub macOS runner build is **not** evidence that your physical A7A0, 3072x1920 panel or USB-C display works. E1.0 intentionally does not solve HEVC hardware encoding, BGRA native pixel-transfer crashes or guarantee 120 Hz. The D1.1 source files and video diagnostic tools remain in this E branch as historical reference only; **only the D archived header is copied into the E build**, not its `kern_xe.cpp`.
